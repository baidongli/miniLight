# Publishing to the App Store & Google Play

The CI is wired so that **builds keep working with no secrets** (you get a
sideloadable APK and an unsigned iOS app). The moment you add the secrets
below, the same pipeline produces store‑ready artifacts and uploads them.

Things only **you** can do are marked 👤. Everything else is already in the
repo.

---

## 0. Privacy policy URL (needed by both stores)

After this branch is merged to `main`:

1. 👤 Repo **Settings → Pages → Build and deployment → Source: GitHub
   Actions**.
2. The `Deploy site` workflow publishes:
   `https://baidongli.github.io/minilight/privacy-policy.html`

Use that URL in both store listings.

## 1. Google Play

### You do once 👤
1. Pay the **one‑time $25** and create a Google Play Console account.
2. Create the app; package name **`com.minilight.minilight`** (permanent).
3. Generate an **upload keystore** on any machine with a JDK:
   ```bash
   keytool -genkey -v -keystore upload-keystore.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
4. In Play Console enable **Play App Signing** (recommended) and register
   this upload key.
5. Create a **service account** (Play Console → Setup → API access),
   grant it release permissions, download its JSON.

### Add these GitHub repo Secrets 👤
| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 upload-keystore.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | store password |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | key password |
| `PLAY_SERVICE_ACCOUNT_JSON` | full service‑account JSON |

Result: every push builds a signed **`.aab`** and uploads it to the Play
**internal testing** track. Promote to production from the Play Console
when ready. First upload of a brand‑new app must be done manually once via
the Console (Google's requirement); after that the action takes over.

### Store listing assets 👤 (Console upload)
App icon (auto from the app), 512×512 icon, 1024×500 feature graphic,
phone screenshots, short/full description, privacy URL (above), Data
Safety form (declare: Camera — not collected/stored; Location — optional,
on‑device only, not shared), content rating questionnaire.

## 2. App Store (individual Apple Developer account)

### You do once 👤
1. Enrol in the **Apple Developer Program ($99/yr)**. An individual
   account shows your legal name as the seller.
2. App Store Connect → **+ New App**, bundle ID
   **`com.minilight.minilight`**.
3. Create an **App Store Connect API key** (Users and Access → Integrations
   → keys), role *App Manager*. Note the **Key ID** and **Issuer ID**,
   download the `AuthKey_XXXX.p8`.
4. Find your **Team ID** (Apple Developer → Membership).

### Add these GitHub repo Secrets 👤
| Secret | Value |
| --- | --- |
| `APPSTORE_API_KEY_ID` | the key id |
| `APPSTORE_API_ISSUER_ID` | the issuer id |
| `APPSTORE_API_KEY_BASE64` | `base64 -w0 AuthKey_XXXX.p8` |
| `APPLE_TEAM_ID` | 10‑char team id |

Result: the iOS job archives with automatic signing
(`-allowProvisioningUpdates` using the API key creates the distribution
cert + profile), exports an App Store IPA, and uploads it to
**TestFlight**. Submit for review from App Store Connect once it appears.

### Store listing assets 👤 (App Store Connect)
App icon (auto), screenshots for 6.7″ and 6.5″ (and iPad if you enable
it), description, keywords, support URL, privacy URL (above), the **App
Privacy** questionnaire (Camera: used, not linked to identity, not for
tracking; Location: optional, app functionality, not linked, not tracking),
and age rating.

## 3. Versioning

`pubspec.yaml` holds the marketing version (`0.0.1`). Bump it for each
public release. The CI build number comes from the run number, so every
upload is unique without manual edits.

## Notes / known iteration points

- The Android `build.gradle.kts` template is regenerated by
  `scripts/configure_android_signing.sh`. If a future Flutter changes the
  default Gradle DSL, that template may need a tweak — the CI log will say
  so clearly.
- iOS automatic signing via API key needs the app record to exist in App
  Store Connect first (step 2.2).
- Replace the placeholder launcher icon (`assets/icon/icon.png`) with real
  artwork before a public launch; the pipeline picks up any replacement
  automatically.
